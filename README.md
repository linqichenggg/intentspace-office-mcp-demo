# IntentSpace オフィスデータ MCP デモ

オフィスデータを検索・集計する、読み取り専用の MCP Server とローカル Web 画面です。Web 画面から MCP Client を通じて独立したサーバープロセスを呼び出し、結果と参照元を確認できます。

画面で条件を選んで照会できるほか、架空データでは OpenAI GPT に自然言語で質問できます。GPT が必要な MCP ツールを選び、実際の結果をもとに回答します。変化の自動検知、企業システムへの予約の作成・変更、リアルタイムの空き状況判定は未接続です。ローカル開発中のRPG画面では、独立した模擬予約を操作できます。

## ローカル開発中：社員の1日と管理画面

`npm start` 後、社員画面は `http://127.0.0.1:4180/office.html`、管理画面は `http://127.0.0.1:4180/admin`。2026-10-20のGPT出力制約・レイアウト修正版はポート4188です。利用者の承認により再起動し、模擬記録を消去して09:00からの空状態にしました。4192は独立した確認環境として残しています。同じポートの社員・管理画面を組み合わせてください。ローカルの従来履歴画面は `/`、Cloudflare版の従来履歴画面は `/history` です。クラウドの社員・管理画面と保存方法は後述します。

### 社員の操作

1. 日本語・英語で1日の予定を入力します。例：「午前は資料作成に集中します。午後に4人で45分、モニターを使って企画を相談したいです。15:00から18:00は別の予定があります。」
2. 「予定を整理する」で、個人作業・会議・不在の時間を分離します。会議だけについて既存MCPの `search_spaces` / `query_reservations` を呼び、人数・設備・部屋の重複と社員自身の予定をプログラムで検証します。柔軟な時間帯は15分刻みで候補を探します。
3. 各提案の条件・部屋を確認し「この内容で予約」を押します。この段階では小人は移動しません。足りない情報は「条件を補う」で編集し、計画全体の制約を維持して再検索できます。未知の設備を勝手に満たした扱いにしません。
4. 「会議を開始（模擬）」で開始イベントを発生させます。予定開始時刻に模擬時計を移し、小人Aが会議室へ移動し、部屋と管理画面が「会議中」になります。
5. 「会議を終了（模擬）」で予定終了時刻へ進み、小人が受付へ戻ります。予約済みの会議は取消可能です。進行中は終了操作が必要です。固定装飾の社員Bは削除しました。
6. 取消済みの記録・提案には「再予約の候補を探す」を表示します。保存された日付・開始時刻・人数・設備を使って、LLMを再呼出しせず空きを確認します。候補を本人が確認して初めて別IDの新予約を作成し、その新記録を表示します。旧取消記録は履歴に残します。元の提案が期限切れでも再検索でき、空きがない場合は条件の補完・再検索へ進めます。

同じ会議の再入力や再送は既存記録へ誘導します。同じ計画内の重複も新たな提案に増やしません。GPTが別表現を同じ会議と推測した場合は、既存の会議を使うか、別会議として探すかを本人に確認します。既存会議を自動変更・取消しません。別会議の重複時間は、部屋が異なる場合も社員Aの予定として拒否します。

### 他の人が予約する会議に参加する

提案の「この会議は自分で予約しない」を押し、実際に参加する会議室と開始時刻を本人が指定します。「参加先を登録（予約しない）」の後は、予約確認を経由せず「会議を開始（模擬）」を使用できます。開始で小人が指定室へ移り、終了で受付へ戻ります。

これは本人申告の参加記録で、予約レコードは増やしません。既存予約がある部屋も指定できますが、他者の予約の存在・主催者との対応は未確認です。人数・設備・営業時間・本人の集中作業、不在及び別会議との重複は検査します。参加予定の取消と再登録は他者の予約を変更せず、再登録は新しい参加IDへ接続します。参加登録や開始・終了にLLMやKeyは不要です。

管理画面にも「本人申告の参加記録・予約操作なし」と表示し、予約総数には加算しません。予約の編集・削除・再予約APIでは参加記録を変更できません。参加開始中は模擬的な使用状態へ反映しますが、終了しても他者の元の予約を解放・取消しません。`POST /api/office/attendance` は既存提案ID、手動指定の `space_id` と `time` を受け取り、取消後は参加記録の `meeting_id` から再登録できます。

### GPTとローカル解析

無料ローカル解析は、一般的な日本語・英語の日時・人数・所要時間・朝/午後の時間帯に対応する限定的なパーサーです。任意の文意を理解するAIとしては扱いません。中国語は新しい日程入力の対応言語に含めません。

「API設定」で自身のKeyを入力するとGPT解析を選択します。GPTは1日の複数の予定、柔軟な条件、不足情報、既存会議との意味的な一致候補を構造化します。モデルの結果をサーバーで再検証し、空き判定・予約・状態変更はプログラムが実行します。GPT自体に予約権限は渡しません。

GPTの返却形式は `input_status` と `activities` に限定します。自由文の `questions` / `unclear`、部屋の選択や予約命令は受け付けません。曖昧さは `uncertainties` の有限な項目種別と入力原文の引用 `evidence` で表し、引用が原文に存在するかサーバーで検証します。形式違反や根拠のない引用は拒否し、新しい解析が失敗した場合は古い確認可能な提案を画面から除きます。保存済みの予約は維持します。

参加者名は任意です。合計人数・所要時間と有効な時間帯があれば、正確な開始時刻を要求せずプログラムが候補を探します。欠けた値は `null` とし、必要項目の不足はプログラムが判定します。実際に矛盾する時刻等は固定の項目別メッセージで表示し、条件を手動補完できます。集中作業・不在は会議の制約として保持し、未知の必須設備を満たした扱いにしません。旧形式の内部計画に対する余分な追問の正規化は互換処理として残しています。

GPT解析では、入力計画・基準日・この架空ワークスペースの既存会議の必要最小限の要約を送信し、API料金が発生します。企業CSV・個人ディレクトリは送りません。Keyは `ApiSession` のページメモリだけで保持し、入力欄から消去します。再読み込み・離脱・手動消去で破棄し、ディスク、Cookie、ブラウザー保存領域には保存しません。ナビゲーション後は再設定が必要です。開発検証は模擬モデル応答を使用し、実モデルの有料呼出しは行っていません。

予約の確認は候補カードで行い、GPTに時刻の同意を求めさせません。本当に `needs_input` の提案がある場合は、その提案名と未解決条件を表示します。活動なし・非対応言語もプログラムの固定メッセージで説明します。[OpenAI公式ドキュメント](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)も示す通り、構造化出力だけでは意味の誤りを完全には防げません。原文引用の存在確認も意味の正しさ全般を保証せず、実モデルが条件を誤解する可能性は残ります。

### 管理画面とデータ境界

管理画面は社員と同じ木質・ピクセルオフィスの視覚言語を使用します。日本語/Englishの切替は両画面の操作・状態・エラー・ナビゲーションを更新します。利用者の元の入力やMCPの原データは翻訳・改変しません。PCは固定の単画面、狭い画面は区画切替、一覧と詳細はページ切替で表示します。

- 「現在の模擬オフィス」：社員と同じ模擬カレンダーを表示し、システムの初期予約を含めて検索・追加・編集・削除・復元できます。日付範囲、スペース、状態、議題・予約者名で検索します。追加・編集では議題、日付、開始時刻、所要時間、人数、部屋、予約者の表示名、社員Aとの関連、設備条件を指定します。社員Aに関連付けると社員画面の予約一覧にも表示します。
- 保存時に部屋の定員・設備・09〜18時の利用時間・日付範囲・予約重複を検査します。社員Aの予約は別室でも本人の時間重複を拒否します。編集は予約済みのみ、進行中は編集・削除不可。終了・取消済みは履歴として保持し、内容の書換えはできません。
- 削除は論理削除です。「削除済み」で検索して復元できます。予約済み記録の復元時は空きを再検査し、他の予約と重なる場合は拒否します。管理操作をイベント履歴に残し、版番号で古い画面からの上書き、操作IDで二重送信を防ぎます。これらは模擬動作で、本番の監査基盤・認証ではありません。
- ページが表示中の場合のみ5秒ごとに状態を同期します。これはローカル画面の同期で、企業のイベント監視・外部通知ではありません。最新のGPT出力制約版は社員・管理者ともポート4188です。
- 「予約と利用」「スペース一覧」「予約明細」「未利用の確認」：従来のMCPと2026年2月の固定架空サンプルを照会。実際のMCP応答、根拠、同条件の前回結果との比較、独立した4段階の変化デモを確認できます。
- 「AIに質問」：従来のGPT/MCPループを使用し、架空の履歴サンプルを検索・集計します。今日の模擬予約はこのAI照会の対象外であることを明示します。

共有ワークスペースは本機の社員A向け単一シミュレーションです。ページを閉じても予約はサーバーメモリに残り、再読み込み・社員/管理画面切替で参照できます。サーバー再起動で消去します。最大200会議、提案は30分・最新30計画まで。管理画面の切替は権限認証ではなく、本番運用のテナント分離・ログインは未実装です。元の単発照会APIの独立セッション契約は互換性のため保持します。

部屋・設備・日程は独立した架空設定です。C-04は4人・モニター・白板・静音、M-02は6人・モニター・ビデオ会議、F-12は1人個人席・モニター・静音。毎日C-04の14〜15時、M-02の11〜12時、F-12の10〜11時に既存模擬予約があります。新しい1日計画は会議の割当を対象とし、個人作業は会議と重ならないための制約に使い、席の予約は作成しません。営業時間09〜18時、JST今日から30日先。参加者カレンダー・参加同意・リアルタイム入退室は未接続です。

初期の模擬予約は管理画面で確認・編集・削除できます。`POST /api/office/workspace/reset` に `{"confirmed":true}` を送ると、このローカルサービス内の予約・初期予約・提案・イベントをすべて消去し、模擬時刻を09:00へ戻します。確認なし・別Origin・GETは拒否します。リセットは復元不可です。企業CSV・API Keyには触れません。サーバーを再起動すると初期設定の予約は再生成されます。

ローカルCRUD API：`GET /api/office/admin/reservations`（検索とページング）、`POST /api/office/admin/create|update|delete|restore`（変更）。変更には `confirmed:true` とUUIDの `operation_id`、既存記録の変更には `meeting_id` と `expected_version` が必要です。既存の読み取り専用MCPツール、企業データ、履歴照会画面は変更しません。ルームマスターの編集と本番認証は対象外です。

## 予約未利用のルール判定（試験機能）

読み込み済みの予約履歴を手動で走査する機能です。変化の自動検知や通知配信は行いません。閾値は企業と合意した基準ではなく、利用シナリオを検討するための試験設定です。

初期条件は、同じスペース・指定期間について次の3条件をすべて満たすことです。

- 判定対象の予約が10件以上。
- 未利用が3件以上。
- 未利用割合が30%以上。

判定対象は `is_reserved=true` かつ `is_used` が `true` / `false` の記録です。未利用はそのうち `is_used=false`。事前キャンセルと不明なフラグは判定から除外し、除外件数も表示します。母数0件の場合は割合を計算せず「サンプル不足」とします。通常の予約集計にある `is_used!=true` とは不明値の扱いが異なります。

画面では「確認候補」「閾値未満」「サンプル不足」を区別します。候補には期間、件数、割合、固定文の提案、参照元を確認できる予約記録を添えます。原因、浪費、予約の解放可否は断定しません。各スペースの根拠は最大5件です。追加の記録は予約明細の期間・スペース・状態フィルターで確認できます。

同じデータ・期間・条件では同じ候補IDを返し、再実行時は画面を置き換えます。通知の配信履歴や重複配信制御は今後の範囲です。全体件数と表示件数を区別し、MCPでは `offset` / `limit` で追加照会できます。

### 架空データで試す

1. 「未利用の確認」を開き、2026-02-01〜2026-02-28で確認します。初期条件では3スペースともサンプル不足になります。
2. 判定に必要な予約数を `2`、未利用件数を `1`、割合を `50` に変更して「ルールで確認する」を押します。

### 前回の確認結果との比較

「未利用の確認」では、初回の成功した確認結果をページ内の比較基準として保持します。2回目以降、同じ期間・スペースの絞り込み・ルール・データ範囲・集計方法の版で行った結果と比較し、スペースIDで次を区別します。

| 前回 → 今回 | 比較結果 |
| --- | --- |
| 閾値未満 → 確認候補 | 新規の候補 |
| 確認候補 → 確認候補 | 継続中 |
| 確認候補 → 閾値未満 | 条件を満たさなくなった（問題解決は断定しない） |
| 片方がサンプル不足・状態不明を含む・片方に空間の記録がない | 判断保留 |
| 閾値未満 → 閾値未満 | 変化なし |

比較できた結果を次回の基準に更新します。同じデータを再確認しても新規候補として加算しません。期間や閾値などを変更した場合は比較を行わず、元の基準を保持します。新しい条件で比較を始める場合は「今回を基準にする」を押してください。初回の基準作成も新規候補の発生とは扱いません。

基準は `session.js` の `ReviewComparison` がページメモリ内だけで保持し、再読み込み・離脱で消去します。保存領域やDBには記録せず、基準をサーバーへ送信しません。`compareReviewSnapshots` は比較のみを行う共有の純粋関数です。MCPの `detect_unused_reservations` 応答には、表示ページとは独立した全対象スペースの小さな比較用スナップショットを含めます。通常の結果の `limit` / `offset` によって、見えていない空間を問題解消と誤認しないためです。

比較時にはデータ種別と組織ID集合に基づく範囲識別子も確認します。ただし、これは本デモの比較防止策であり、本番のテナント認証・権限管理ではありません。記録の欠損、重複ID、数値と判定の矛盾があるスナップショットは拒否します。

通常検索の公開CSVは固定です。連続確認では「データ内容は前回と同じ」と表示されます。実データ更新、自動監視、メール・Discordなどへの配信は未実装です。

## GPT を使う：毎回 Key を入力

1. 「API 設定」で自分の OpenAI API Key と GPT モデル名を入力します。初期値は `gpt-4.1-mini` です。利用できるモデルは自身の API アカウントで確認してください。
2. 「このページで使用する」を押すと入力欄から Key が消え、このページの JavaScript メモリ内だけで保持されます。
3. 「AI に質問」で質問します。例：「2026年2月の予約と未利用をスペース別に集計して」。
4. 回答の下で「GPT が呼び出した MCP ツール」を開き、引数と結果を確認できます。
5. 「退出・Key を消去」、再読み込み、ページを閉じる操作で Key と会話履歴をクリアします。再開時は再入力が必要です。

API KeyとGPT会話履歴は localStorage、sessionStorage、Cookie、DB、KV に保存しません。クラウドのCookieはワークスペース識別専用で、Keyを含みません。抽出された会議予定は前述の通り別途保存します。Key は認証ヘッダーでこのサーバーに送信し、固定の OpenAI 公式 API に転送します。サーバーはリクエストの処理中だけ Key を使用し、アプリログや応答には出力しません。任意の API 転送先は指定できません。Cloudflare の Worker ログ機能もこの設定では無効です。

ブラウザー自身のパスワード保存機能は利用しないでください。このアプリが Key を保存しないことと、OpenAI 側のデータ保持方針は別の事項です。Responses API のリクエストは `store:false` に設定していますが、これをゼロデータ保持の保証として扱わないでください。退出時にページ側の待機を中止しても、すでに OpenAI に届いたリクエストは処理・課金される場合があります。

API 料金は入力した Key の所有者に発生します。Key がなくても通常の検索・集計・参照元確認は利用できます。最大6回のモデルリクエスト・12回のツール呼び出し・90秒の処理タイムアウトを設けています。

企業サンプルの外部 AI 送信は初期状態で無効です。ローカルで GPT を試す場合も、次のように架空データを明示してください。

```sh
OFFICE_DATA_DIR=./demo-data npm start
```

実装・検証は [OpenAI の function calling 仕様](https://developers.openai.com/api/docs/guides/function-calling)に従います。モデル検証には模擬応答を使用し、実際の Key による有料モデル呼び出しは行っていません。

## 集計条件と制約

- 応答には対象期間、読み込み時刻、元ファイルの SHA-256 と注意事項を付けます。
- 元データの更新時刻は不明です。読み込み時刻を現場の状態更新時刻として扱いません。
- 日付検索は元データの予約開始日を基準とします。検索期間は両端を含みます。対象期間外の検索は拒否します。
- 企業サンプルの JST 項目に UTC 表記があるため、時刻の意味は確認が必要です。自動的な時差変換は行いません。
- 「事前キャンセルを除く未利用」は `is_reserved=true` かつ `is_used!=true` の件数です。バーはその件数を `is_reserved=true` の件数で割った割合です。
- 時間ベースの稼働率、改善効果、予約の自動解放可否は、この集計だけでは判断できません。
- 定員は元データの登録値です。空欄と 0 は不明として扱います。

## 構成

```text
Web 画面（index.html / app.js / styles.css）
  → MCP Client（web.js）
  → MCP Server（server.js）
  → 読み込み・検索・集計（data.js）
```

```text
Cloudflare Web / GPT質問（ai.js / session.js）
```

`test.js` は実際の MCP 接続を使用し、ツール一覧、集計と明細の一致、参照元、日付の入力エラーなどを確認します。

`integration.test.js` はルールの境界・取消/不明値の除外・母数0・根拠・繰り返し・ページング・無効入力に加え、変更比較の整合性、画面デモの4ステップ・参照元・通常データとの分離・条件注入の拒否・リクエスト間の独立性を検証します。Keyの消去と処理中断、保存APIを使わないこと、模擬GPTによる実際のMCP呼び出し、企業データ送信の拒否、エラー時のKey保護、リクエスト上限、遠隔MCP、公開資産の範囲も検証します。追加の判定用データとデモバッチはメモリ内だけで生成し、CSVファイルは変更しません。

`npm start` のローカルサービスは本機のみで待ち受けます。公開版はCloudflareで配信します。どちらも個人の識別情報は返しません。企業データ用の遠隔認証やマルチテナント権限制御は未実装です。
