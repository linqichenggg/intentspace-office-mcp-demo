### 本機のデフォルトAPI Key（2026-10-30、本機専用設定）

3. ページに別のKeyを入力した場合は、その一時Keyとモデルを優先します。一時Keyが失敗しても本機Keyで自動再試行しません。「Keyを消去」で一時Key・会話と進行中処理を消去し、本機のデフォルトに戻ります。ページ入力を `.env.local` へ書き戻す機能はありません。
4. 本機のデフォルトを無効にする場合は、自分でファイルの `OPENAI_API_KEY=` を空にして保存し、画面で読み直します。公開サイトのAPI設定入口とページ内だけの一時Keyは維持します。

### カレンダーからホームへ取り込む

カレンダーは日程の保存・編集、ホームはAgentへの依頼に使用します。月曜始まりの月表示、日付ごとの件数と摘要、前後月・今日への移動、日付を選んだ追加・編集・取消に対応しています。記録範囲は1900〜2100年、有効な予定は1日12件・全体200件、同日内15〜480分です。取消済みは有効件数に含めず、履歴・予約との関連は保持します。履歴を含む保存件数は2000件までで、既存のワークスペース保存サイズ上限も適用します。上限到達時も自動削除せず、既存予定の編集・取消を継続できます。夜間の私用も記録できます。Google/OutlookやICSファイルの取込は未接続です。

1. 「カレンダー」で予定を保存し、「ホームで日程を取り込む」で戻ります。保存や取り込みの操作だけではAIを呼びません。
2. ホームの入力元を「カレンダーから取り込む」にし、今日から30日先までの対象範囲を指定して「日程を取り込む」を押します。これはシステム内の模擬日程を取り込む操作です。
3. 日程のプレビューを確認します。日程の変更はカレンダーで保存して再度取り込みます。「補足条件」は選んだ全日程に適用します。変更すると全対象の解釈を再分析します。
4. API設定後、ホームの既存の緑ボタン「予定を整理する」を押します。日程ごとの固定ID・版数、選択モデル、補足条件を比較し、未処理・変更分だけをAgentへ渡します。変更のない事項は待処理として再度モデルへ送りません。必要な既存予約・競合情報だけを文脈として使います。

### 現在の予約と履歴

- 社員画面の「現在の予約」は、有効な予約・参加予定と利用中の記録だけを表示します。取消・終了・削除済み、開始期限を過ぎた未開始の記録は「履歴」に分離します。未開始の期限超過は実施済みとは扱わず、実施状況が不明な元の状態を保持します。
- 再予約候補を検索した段階では旧取消記録を変更しません。確認が成功した時だけ `rebooked_from` / `replaced_by` を保存し、旧履歴は「後続の記録を見る」へ切り替えます。複数回の取消・再予約では最新の後続記録へ移動します。取消済みの旧カードから予約を増殖させません。
- 予約確認前に空きや元の記録が変更された場合は確認を拒否し、旧履歴の関連付けを残しません。再登録した参加記録も同じ履歴分離に対応し、同じ登録の再送は同じ記録を返します。別の人の予約は変更しません。

### 管理者の操作

- 通常の「削除」は復元できる論理削除です。「削除済み」の各行には「復元」と「完全に削除」を表示します。完全削除は対象を表示した確認画面で「復元できない」ことをチェックして実行します。未削除の予約へ直接実行することはできません。
- 完全削除後は予約本体・社員履歴・管理者一覧から除去し、関連する保存済み提案と応答キャッシュも無効化します。以前の作成・復元操作の再送で内容を戻しません。再予約の前後のリンクは残存する記録へつなぎ直し、他の予約は削除しません。元の操作内容は除去し、識別IDと削除時刻だけの最小監査を保持します。元に戻す機能はありません。企業CSVは変更しません。

## 予約未利用のルール判定（試験機能）

読み込み済みの予約履歴を手動で走査する機能です。変化の自動検知や通知配信は行いません。閾値は企業と合意した基準ではなく、利用シナリオを検討するための試験設定です。

初期条件は、同じスペース・指定期間について次の3条件をすべて満たすことです。

- 判定対象の予約が10件以上。
- 未利用が3件以上。
- 未利用割合が30%以上。

判定対象は `is_reserved=true` かつ `is_used` が `true` / `false` の記録です。未利用はそのうち `is_used=false`。事前キャンセルと不明なフラグは判定から除外し、除外件数も表示します。母数0件の場合は割合を計算せず「サンプル不足」とします。通常の予約集計にある `is_used!=true` とは不明値の扱いが異なります。

画面では「確認候補」「閾値未満」「サンプル不足」を区別します。候補には期間、件数、割合、固定文の提案、参照元を確認できる予約記録を添えます。原因、浪費、予約の解放可否は断定しません。各スペースの根拠は最大5件です。追加の記録は予約明細の期間・スペース・状態フィルターで確認できます。

同じデータ・期間・条件では同じ候補IDを返し、再実行時は画面を置き換えます。通知の配信履歴や重複配信制御は今後の範囲です。全体件数と表示件数を区別し、MCPでは `offset` / `limit` で追加照会できます。

### 前回の確認結果との比較

「未利用の確認」では、初回の成功した確認結果をページ内の比較基準として保持します。2回目以降、同じ期間・スペースの絞り込み・ルール・データ範囲・集計方法の版で行った結果と比較し、スペースIDで次を区別します。

| 前回 → 今回 | 比較結果 |
| --- | --- |
| 閾値未満 → 確認候補 | 新規の候補 |
| 確認候補 → 確認候補 | 継続中 |
| 確認候補 → 閾値未満 | 条件を満たさなくなった（問題解決は断定しない） |
| 片方がサンプル不足・状態不明を含む・片方に空間の記録がない | 判断保留 |
| 閾値未満 → 閾値未満 | 変化なし |

比較時にはデータ種別と組織ID集合に基づく範囲識別子も確認します。ただし、これは本デモの比較防止策であり、本番のテナント認証・権限管理ではありません。記録の欠損、重複ID、数値と判定の矛盾があるスナップショットは拒否します。

## GPT を使う：毎回 Key を入力

1. 「API 設定」で自分の OpenAI API Key と GPT モデル名を入力します。初期値は `gpt-6.1-sol` です。利用できるモデルは自身の API アカウントで確認してください。
2. 「このページで使用する」を押すと入力欄から Key が消え、このページの JavaScript メモリ内だけで保持されます。
3. 「AI に質問」で質問します。例：「2026年2月の予約と未利用をスペース別に集計して」。
4. 回答の下で「GPT が呼び出した MCP ツール」を開き、引数と結果を確認できます。
5. 「退出・Key を消去」、再読み込み、ページを閉じる操作で Key と会話履歴をクリアします。再開時は再入力が必要です。

API KeyとGPT会話履歴は localStorage、sessionStorage、Cookie、DB、KV に保存しません。クラウドのCookieはワークスペース識別専用で、Keyを含みません。抽出された会議予定は前述の通り別途保存します。Key は認証ヘッダーでこのサーバーに送信し、固定の OpenAI 公式 API に転送します。サーバーはリクエストの処理中だけ Key を使用し、アプリログや応答には出力しません。任意の API 転送先は指定できません。Cloudflare の Worker ログ機能もこの設定では無効です。

ブラウザー自身のパスワード保存機能は利用しないでください。このアプリが Key を保存しないことと、OpenAI 側のデータ保持方針は別の事項です。Responses API のリクエストは `store:false` に設定していますが、これをゼロデータ保持の保証として扱わないでください。退出時にページ側の待機を中止しても、すでに OpenAI に届いたリクエストは処理・課金される場合があります。

API 料金は入力した Key の所有者に発生します。Key がなくても通常の検索・集計・参照元確認は利用できます。最大6回のモデルリクエスト・12回のツール呼び出し・90秒の処理タイムアウトを設けています。

企業サンプルの外部 AI 送信は初期状態で無効です。ローカルで GPT を試す場合も、次のように架空データを明示してください。

```sh
OFFICE_DATA_DIR=./demo-data npm start
```

実装・検証は [OpenAI の function calling 仕様](https://developers.openai.com/api/docs/guides/function-calling)に従います。モデル検証には模擬応答を使用し、実際の Key による有料モデル呼び出しは行っていません。

## 集計条件と制約

- 応答には対象期間、読み込み時刻、元ファイルの SHA-256 と注意事項を付けます。
- 元データの更新時刻は不明です。読み込み時刻を現場の状態更新時刻として扱いません。
- 日付検索は元データの予約開始日を基準とします。検索期間は両端を含みます。対象期間外の検索は拒否します。
- 企業サンプルの JST 項目に UTC 表記があるため、時刻の意味は確認が必要です。自動的な時差変換は行いません。
- 「事前キャンセルを除く未利用」は `is_reserved=true` かつ `is_used!=true` の件数です。バーはその件数を `is_reserved=true` の件数で割った割合です。
- 時間ベースの稼働率、改善効果、予約の自動解放可否は、この集計だけでは判断できません。
- 定員は元データの登録値です。空欄と 0 は不明として扱います。

## 構成

```text
Web 画面（index.html / app.js / styles.css）
  → MCP Client（web.js）
  → MCP Server（server.js）
  → 読み込み・検索・集計（data.js）
  → CSV
```

```text
Cloudflare Web / GPT質問（ai.js / session.js）
  → worker.js / cloud-api.js
  → GPTのツール選択（llm.js / OpenAI Responses API）
  → MCP Client（mcp-client.js / InMemoryTransport）
  → MCP Server（mcp-server.js）
  → 共有検索・集計処理（queries.js）
  → 架空CSVのみ
```

`server.js` は共有 MCP Server を stdio で起動する入口です。`data.js` はローカル用のCSV読み込み、`queries.js` はローカルとクラウドで共通の計算処理です。`build-assets.js` は許可した12個のWebファイルのみを `.build/assets/` にコピーします。

`test.js` は実際の MCP 接続を使用し、ツール一覧、集計と明細の一致、参照元、日付の入力エラーなどを確認します。

`integration.test.js` はルールの境界・取消/不明値の除外・母数0・根拠・繰り返し・ページング・無効入力に加え、変更比較の整合性、画面デモの4ステップ・参照元・通常データとの分離・条件注入の拒否・リクエスト間の独立性を検証します。Keyの消去と処理中断、保存APIを使わないこと、模擬GPTによる実際のMCP呼び出し、企業データ送信の拒否、エラー時のKey保護、リクエスト上限、遠隔MCP、公開資産の範囲も検証します。追加の判定用データとデモバッチはメモリ内だけで生成し、CSVファイルは変更しません。

`npm start` のローカルサービスは本機のみで待ち受けます。公開版はCloudflareで配信します。どちらも個人の識別情報は返しません。企業データ用の遠隔認証やマルチテナント権限制御は未実装です。
