# IntentSpace オフィスデータ MCP デモ

オフィスデータを検索・集計する、読み取り専用の MCP Server とローカル Web 画面です。Web 画面から MCP Client を通じて独立したサーバープロセスを呼び出し、結果と参照元を確認できます。

画面で条件を選んで照会できるほか、架空データでは OpenAI GPT に自然言語で質問できます。GPT が必要な MCP ツールを選び、実際の結果をもとに回答します。変化の自動検知、予約の作成・変更、リアルタイムの空き状況判定は未実装です。

## 公開範囲

公開リポジトリにはソースコードと架空のデモデータのみを含みます。`demo-data/` の 3 スペース・6 件の予約は、動作確認用に作成したものです。企業提供の CSV、フロアマップ、個人情報、認証情報は含みません。

## 起動方法

Node.js 22 以降を使用してください。

```sh
npm ci
npm test
npm start
```

ブラウザーで http://127.0.0.1:4180 を開きます。

1. 「予約と利用」で、指定期間の記録をスペース別に集計します。
2. 「スペース一覧」で、名前からスペースを検索します。
3. 「予約明細」で、状態や日時を確認し、「参照元を確認」を押します。
4. 「ツール呼び出しと返却データ」を開くと、入力パラメーターと実際の MCP 応答を確認できます。
5. 「未利用の確認」で、試験用のルールによる確認候補・根拠・管理者への提案を確認します。LLM・API Key は不要です。

## 予約未利用のルール判定（試験機能）

読み込み済みの予約履歴を手動で走査する機能です。変化の自動検知や通知配信は行いません。閾値は企業と合意した基準ではなく、利用シナリオを検討するための試験設定です。

初期条件は、同じスペース・指定期間について次の3条件をすべて満たすことです。

- 判定対象の予約が10件以上。
- 未利用が3件以上。
- 未利用割合が30%以上。

判定対象は `is_reserved=true` かつ `is_used` が `true` / `false` の記録です。未利用はそのうち `is_used=false`。事前キャンセルと不明なフラグは判定から除外し、除外件数も表示します。母数0件の場合は割合を計算せず「サンプル不足」とします。通常の予約集計にある `is_used!=true` とは不明値の扱いが異なります。

画面では「確認候補」「閾値未満」「サンプル不足」を区別します。候補には期間、件数、割合、固定文の提案、参照元を確認できる予約記録を添えます。原因、浪費、予約の解放可否は断定しません。各スペースの根拠は最大5件です。追加の記録は予約明細の期間・スペース・状態フィルターで確認できます。

同じデータ・期間・条件では同じ候補IDを返し、再実行時は画面を置き換えます。通知の配信履歴や重複配信制御は今後の範囲です。全体件数と表示件数を区別し、MCPでは `offset` / `limit` で追加照会できます。

### 架空データで試す

1. 「未利用の確認」を開き、2026-02-01〜2026-02-28で確認します。初期条件では3スペースともサンプル不足になります。
2. 判定に必要な予約数を `2`、未利用件数を `1`、割合を `50` に変更して「ルールで確認する」を押します。
3. Demo Meeting A が確認候補になります。判定対象2件・未利用1件・50%で、根拠は `demo-r3` です。Meeting Bは母数1件でサンプル不足、Boothは事前キャンセルを除くと母数0件です。
4. 割合を `50.1` にするとMeeting Aは閾値未満になります。

この低い閾値は小さな架空データでの動作確認用です。本番の判断基準として使用しないでください。企業データや公開CSVは、この機能のために追加・変更していません。

## MCP ツール

| ツール | 内容 |
| --- | --- |
| `get_data_status` | 対象期間、読み込み時刻、件数、元ファイルのハッシュ値と制約 |
| `search_spaces` | 名称・種別・登録定員で検索 |
| `query_reservations` | 開始日・スペース・状態による予約検索とページング |
| `summarize_reservations` | スペース別の予約・利用・未利用・状態別件数 |
| `detect_unused_reservations` | 指定期間を試験ルールで走査し、確認候補・除外件数・根拠・提案を返す |
| `get_evidence` | 予約 ID に対応する記録と参照元の論理レコード番号 |

画面のスペース検索では、読み込んだ予約データに登場するスペースを対象にします。予約可能なスペースの現在の一覧を保証するものではありません。

## 他の MCP クライアントから接続

stdio 接続を使用します。クライアントの設定で、`command` に Node.js の実行ファイル、`args` にこのリポジトリの `server.js` の絶対パスを指定します。

```json
{
  "mcpServers": {
    "office-data": {
      "command": "node",
      "args": ["/absolute/path/to/intentspace-office-mcp-demo/server.js"]
    }
  }
}
```

設定形式はクライアントによって異なります。`npm run mcp` でも MCP Server を起動できます。stdio サーバー単体には Web 画面はありません。

## Cloudflare で公開する

公開デモ：[IntentSpace オフィスデータ](https://intentspace-office-demo.linqicheng65.workers.dev)。Discord などで共有できます。表示される記録はすべて架空データです。

公開 Worker は `demo-data/` の架空 CSV だけを読み込みます。ローカルの企業データを読み込む `data.js` は Worker から参照しません。Web 資産も5ファイルに限定し、ソースコード・CSV・認証情報を静的ファイルとして公開しません。

```sh
npm run dev:cloud
npm run check:deploy
npm run deploy
```

`dev:cloud` は http://127.0.0.1:4181 で動作します。公開 URL はデプロイ成功時に Wrangler が表示します。Cloudflare アカウントへのログインが必要です。利用プランの変更は不要な範囲で実施し、料金と利用上限は各アカウントで確認してください。

公開版は `/mcp` に標準 Streamable HTTP の読み取り専用 MCP エンドポイントも提供します。外部クライアントから接続する場合は `<公開URL>/mcp` を指定してください。現在は架空データの公開デモであり、企業データ用の認証・権限管理は未実装です。

## GPT を使う：毎回 Key を入力

1. 「API 設定」で自分の OpenAI API Key と GPT モデル名を入力します。初期値は `gpt-4.1-mini` です。利用できるモデルは自身の API アカウントで確認してください。
2. 「このページで使用する」を押すと入力欄から Key が消え、このページの JavaScript メモリ内だけで保持されます。
3. 「AI に質問」で質問します。例：「2026年2月の予約と未利用をスペース別に集計して」。
4. 回答の下で「GPT が呼び出した MCP ツール」を開き、引数と結果を確認できます。
5. 「退出・Key を消去」、再読み込み、ページを閉じる操作で Key と会話履歴をクリアします。再開時は再入力が必要です。

API Key・会話は localStorage、sessionStorage、Cookie、DB、KV に保存しません。Key は認証ヘッダーでこのサーバーに送信し、固定の OpenAI 公式 API に転送します。サーバーはリクエストの処理中だけ Key を使用し、アプリログや応答には出力しません。任意の API 転送先は指定できません。Cloudflare の Worker ログ機能もこの設定では無効です。

ブラウザー自身のパスワード保存機能は利用しないでください。このアプリが Key を保存しないことと、OpenAI 側のデータ保持方針は別の事項です。Responses API のリクエストは `store:false` に設定していますが、これをゼロデータ保持の保証として扱わないでください。退出時にページ側の待機を中止しても、すでに OpenAI に届いたリクエストは処理・課金される場合があります。

API 料金は入力した Key の所有者に発生します。Key がなくても通常の検索・集計・参照元確認は利用できます。最大6回のモデルリクエスト・12回のツール呼び出し・90秒の処理タイムアウトを設けています。

企業サンプルの外部 AI 送信は初期状態で無効です。ローカルで GPT を試す場合も、次のように架空データを明示してください。

```sh
OFFICE_DATA_DIR=./demo-data npm start
```

実装・検証は [OpenAI の function calling 仕様](https://developers.openai.com/api/docs/guides/function-calling)に従います。モデル検証には模擬応答を使用し、実際の Key による有料モデル呼び出しは行っていません。

## データの差し替え

次の 3 ファイルを、サンプルと同じ項目構成で用意します。

- `spaces.csv`：スペースの名称、種別、定員など
- `reservations.csv`：予約日時、利用・キャンセル状態など
- `reservations_classified_mapping.csv`：予約 ID と会議分類

`OFFICE_DATA_DIR` にディレクトリを指定し、再起動すると読み込まれます。

```sh
OFFICE_DATA_DIR=/absolute/path/to/private-data npm start
```

明示的な指定がなければ、本プロジェクトの既存作業環境にある相対パス `../07_企业数据/2026-09-07_Bitkey/Data` を確認します。このディレクトリが存在しない環境では、公開リポジトリの `demo-data/` を使用します。明示的に指定したパスが無効な場合はエラーになります。

架空データでの検証と起動：

```sh
OFFICE_DATA_DIR=./demo-data npm test
OFFICE_DATA_DIR=./demo-data npm start
```

現在の読み込みは起動時のみです。自動同期、企業 API、データベース接続は今後の対応範囲です。データモデルは提供されたデータの種類をもとに設計し、実運用時には更新データへの接続を想定しています。

## 集計条件と制約

- 応答には対象期間、読み込み時刻、元ファイルの SHA-256 と注意事項を付けます。
- 元データの更新時刻は不明です。読み込み時刻を現場の状態更新時刻として扱いません。
- 日付検索は元データの予約開始日を基準とします。検索期間は両端を含みます。対象期間外の検索は拒否します。
- 企業サンプルの JST 項目に UTC 表記があるため、時刻の意味は確認が必要です。自動的な時差変換は行いません。
- 「事前キャンセルを除く未利用」は `is_reserved=true` かつ `is_used!=true` の件数です。バーはその件数を `is_reserved=true` の件数で割った割合です。
- 時間ベースの稼働率、改善効果、予約の自動解放可否は、この集計だけでは判断できません。
- 定員は元データの登録値です。空欄と 0 は不明として扱います。

## 構成

```text
Web 画面（index.html / app.js / styles.css）
  → MCP Client（web.js）
  → MCP Server（server.js）
  → 読み込み・検索・集計（data.js）
  → CSV
```

```text
Cloudflare Web / GPT質問（ai.js / session.js）
  → worker.js / cloud-api.js
  → GPTのツール選択（llm.js / OpenAI Responses API）
  → MCP Client（mcp-client.js / InMemoryTransport）
  → MCP Server（mcp-server.js）
  → 共有検索・集計処理（queries.js）
  → 架空CSVのみ
```

`server.js` は共有 MCP Server を stdio で起動する入口です。`data.js` はローカル用のCSV読み込み、`queries.js` はローカルとクラウドで共通の計算処理です。`build-assets.js` は許可した5つのWebファイルのみを `.build/assets/` にコピーします。

`test.js` は実際の MCP 接続を使用し、ツール一覧、集計と明細の一致、参照元、日付の入力エラーなどを確認します。

`integration.test.js` はルールの境界・取消/不明値の除外・母数0・根拠・繰り返し・ページング・無効入力に加え、Keyの消去と処理中断、保存APIを使わないこと、模擬GPTによる実際のMCP呼び出し、企業データ送信の拒否、エラー時のKey保護、リクエスト上限、遠隔MCP、公開資産の範囲を検証します。追加の判定用データはテストのメモリ内だけで生成します。

`npm start` のローカルサービスは本機のみで待ち受けます。公開版はCloudflareで配信します。どちらも個人の識別情報は返しません。企業データ用の遠隔認証やマルチテナント権限制御は未実装です。
